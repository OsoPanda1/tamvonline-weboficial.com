# Security Policy

## Scope

This policy covers the static website source, the catalogue metadata, and its build/quality workflow.

## Reporting a vulnerability

Please do not post sensitive exploit details, credentials, tokens, personal information, or attack instructions in a public issue.

If GitHub private vulnerability reporting is enabled for this repository, use that channel. If it is not available, contact a repository maintainer through a mutually known private channel and provide a concise description, affected file or route, reproduction steps, and potential impact. This repository does not currently publish a dedicated security contact address.

## Response and disclosure

The maintainer should acknowledge the report, assess reproducibility and impact, and coordinate remediation and disclosure when practical. No response-time guarantee is made until an operational security contact and service commitment are established.

## Safe reporting

- Never include secrets or live credentials in a report.
- Redact personal data and production logs.
- Do not test systems or deployments that you do not own or have permission to assess.
- Prefer minimal, reproducible proof over destructive testing.
